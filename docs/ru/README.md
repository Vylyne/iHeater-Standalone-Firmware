# Standalone iHeater Firmware

iHeater - это компактное и доступное решение для 3D-принтеров без активной термокамеры или с ограниченными возможностями подключения к материнской плате. Он особенно полезен для моделей с проприетарными платами, где нет свободных разъёмов для вентилятора, нагревателя или термистора. iHeater решает эту задачу простым и универсальным способом.


Может работать самостоятельно с собственной прошивкой как отдельное устройство или под управлением Klipper с подключением к принтеру по USB

![iHeater](../img/iHeater_200.png)

---

## О прошивке

**iHeater** - это прошивка для автономного устройства управления температурой камеры 3D-принтера. 

---

## Назначение

Устройство обеспечивает нагрев и поддержание стабильной температуры внутри камеры 3D-принтера, что критично для печати ABS, ASA и других температурозависимых пластиков с высокой усадкой и низкой адгезией слоев.

## Как настроить прошивку

### Файл `config.h`

В этом файле задаются параметры работы устройства:
Файл находится в папке Core/Inc/config.h

| Параметр                                    | Назначение                                                                                          |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `SELECTED_THERMISTOR_TYPE`                  | Выбор типа термистора (0-5, см. ниже)                                                               |
| `MODE_TEMP_0`-`MODE_TEMP_7`                             | Температуры для каждого режима. Можно задать любое значение, включая дробные, например `MODE_TEMP_4 67.5` |
| `MAX_TEMP`, `MIN_TEMP`                      | Допустимый диапазон температур нагревателя                                                          |
| `MAX_AIR_TEMP`, `MIN_AIR_TEMP`              | Диапазон температур воздуха                                                                         |
| `HEATER_MIN_PWM`                            | Минимальный PWM, при котором система начнёт проверку ответа нагревателя                             |
| `HEATER_RESPONSE_TIMEOUT_MS`                | Время ожидания роста температуры нагревателя (по умолчанию 5 сек)                                   |
| `AIR_TARGET_TIMEOUT_MS`                     | Максимальное время достижения целевой температуры воздуха (по умолчанию 10 мин)                     |
| `TIMER_CLOCK`, `PWM_FREQUENCY`, `PWM_STEPS` | Настройка частоты и качества ШИМ                                                                    |

### Автоматическое включение и выключение r1.1

Макросы
```
#define TRIGGER_ON_TEMP  45.0f
#define TRIGGER_OFF_TEMP 80.0f
#define TRIGGER_MODE MODE_2
```

Отвечают за температуру включения и выключения нагревателя а так же за режим при включении. 

Предположим что термистор триггера расположен в районе нагревателя стола.
С текущими настройками нагрев камеры включится когда температура стола будет 45 и выключится когда температура стола опустится ниже 80, такие параметры приемлемы для большинства пластиков требующих активной термокамеры и не вызывают логических конфликтов при работе.

Так же можно выбрать режим который будет запущен при срабатывании триггера. Например сейчас выбран TRIGGER_MODE MODE_2 и это значит что будет запущен режим MODE_TEMP_2 -  температура в камере 60.0°C

### Работа с iHeater-link (сборка r1.1 pulse)

Сборка `iheater_rev1_1_pulse` рассчитана на совместную работу с модулем iHeater-link на ESP. Модуль получает команды от принтера, портала или мобильного приложения и транслирует уставку камеры в iHeater по одной GPIO-линии. Прошивка iHeater не зависит от стороны принтера и не знает про транспорт — она принимает только число: желаемую температуру воздуха в камере в °C.

#### Подключение

1. Прошейте iHeater сборкой `iheater_rev1_1_pulse` (см. раздел «Как прошить»).
2. Сигнальный провод от iHeater-link подключите к разъёму **TH2** платы iHeater (пин PB1).
3. Общий GND между ESP и iHeater обязателен — используйте отдельный провод земли.
4. Термистор нагревателя оставьте на своём штатном разъёме **TH0**. Термистор воздуха — на **TH1**. Они работают как в любой другой сборке.
5. Разъём триггера в этой сборке не используется (его линия занята цифровым входом).

!!! warning "Никогда не подключайте и не отключайте сигнальный провод при поданном питании."

#### Принимаемые команды

| Код от iHeater-link | Смысл |
|---------------------|--------|
| `0`                 | Выключить нагрев |
| `10`                | Выключить нагрев (согласованный «off-code») |
| `45..90`            | Включить нагрев, уставка воздуха в °C равна коду |
| остальные значения  | Игнорируются, сохраняется предыдущее состояние |

Минимум `45 °C` задан в `config.h` макросом `PULSE_MIN_TARGET`. Максимум ограничен `MAX_AIR_TEMP` (по умолчанию 90 °C).

#### Индикация LED

| Состояние | LED1 | LED2 | LED3 |
|-----------|------|------|------|
| Ожидание первого пакета после включения (до 20 с) | бегущий огонёк LED1 → LED2 → LED3 с шагом 1000 мс | | |
| Связь ОК, нагрев выключен | горит постоянно (heartbeat «связь жива») | погашен | короткая вспышка ~80 мс на каждый принятый пакет |
| Связь ОК, нагрев включён | бегущий огонёк LED1 → LED2 → LED3 с шагом 500 мс | | |
| Потеряна связь (более 1.5 с без пакета после первого подключения) | Все три мигают синхронно; устройство перезагружается с кодом ошибки `0x08` (`ERROR_LINK_LOST`). Нагреватель выключен. | | |

Штатные ошибки (перегрев, обрыв термистора, нагреватель не отвечает) работают так же, как в аналоговых сборках — см. раздел «Как быть в случае ошибки».

#### Поведение при потере связи

После включения питания iHeater и iHeater-link могут стартовать одновременно. Модулю iHeater-link нужно время на инициализацию Wi-Fi и подключение к источнику команд, поэтому в первые **20 секунд** после старта прошивка iHeater **не считает отсутствие пакетов ошибкой** и показывает медленный бегущий огонёк (шаг 1000 мс) — «жду первого пакета».

Если за эти 20 секунд так и не пришёл ни один корректный пакет — прошивка уходит в `ERROR_LINK_LOST` так же, как и при пропадании связи в штатном режиме.

После того как первый пакет принят, действует обычное правило: пропадание пакетов более чем на 1.5 секунды → ошибка.

Алгоритм при срабатывании ошибки:

1. Прошивка сохраняет в flash код ошибки `0x08` (`ERROR_LINK_LOST`).
2. Перезагружает контроллер.
3. После перезагрузки нагреватель выключен; в течение нового 20-секундного окна снова бегущий огонёк ожидания, дальше — медленное мигание всех LED.
4. Для сброса ошибки удерживайте кнопку MODE при подаче питания, затем отпустите. Устройство вернётся к штатной работе.

#### Кнопка MODE

В pulse-сборке кнопка MODE **не переключает режимы и не запускает калибровку**. Её единственная функция — сброс сохранённой ошибки при старте устройства. Все команды нагрева поступают только от iHeater-link.

### Работа с iHeater Remote (сборка UART)

Сборка `iheater_rev1_1_uart` позволяет Remote (модулю на ESP, одноплатному компьютеру, USB-UART адаптеру) управлять iHeater по Modbus RTU через USART1. Remote задаёт температуру воздуха в камере, читает состояние и температуры воздуха, нагревателя и вспомогательного датчика (TH2) и может сбрасывать часть ошибок. Образ должен оставаться в пределах лимита 30 КБ (две последние страницы flash заняты калибровкой триггера и кодом ошибки).

#### Подключение

Линия использует контакты разъёма USB-C, а не данные USB. Логика 3,3 В.

| Контакт USB-C | Сигнал | Вывод MCU |
|---------------|--------|-----------|
| VBUS | 5 В | питание |
| GND | GND | GND |
| D− | TX iHeater | PA9 (пин 17) |
| D+ | RX iHeater | PA10 (пин 18) |

Линии данных пересекаются: TX у Remote идёт на RX iHeater (D+), RX у Remote — на TX iHeater (D−).

!!! warning "На плате нет стабилизатора 5 В. Питайте её только от 5 В Remote (VBUS). Никогда не подавайте 5 В одновременно с USB и с разъёма JST 5 V."

!!! warning "Никогда не подключайте и не отключайте кабель связи при поданном питании."

!!! warning "Не подключайте сборку UART к порту USB компьютера, кроме режима DFU (удерживается BOOT). Линия связи управляет D− и конфликтует с хостом."

Термистор нагревателя оставьте на **TH0**, термистор воздуха — на **TH1**. Функция триггера в этой сборке отключена.

#### Параметры порта

Modbus RTU, адрес slave 1, 115200 бод, 8N1. Поддерживаются функции 03, 04, 06 и 10; ошибки возвращаются исключениями 0x01 (функция), 0x02 (адрес или состояние), 0x03 (значение) и 0x04 (сбой устройства, возвращается только когда удалённый сброс не может стереть ошибку). На кадры для других адресов, кадры с неверным CRC и коды функций с установленным битом 0x80 ответа нет. Температуры передаются знаковыми 16-битными десятыми долями °C; нечитаемый датчик даёт `0x8000`. Полная карта регистров — в [docs/design/2026-11-19-uart-link-design.md](../design/2026-11-19-uart-link-design.md).

#### Поведение при удержании

После включения уставка равна 0, пока Remote не запишет новую. Если корректных кадров нет **3 с**, iHeater входит в удержание и хранит последнюю уставку. Через **60 с** после входа в удержание (через 63 с после последнего кадра) уставка становится 0. Это не ошибка; нагрев возобновится только после новой уставки.

После каждого включения связь молчит около 5 с, включая перезапуск после удалённого сброса, поэтому Remote должен повторять запрос. Состояние 0 (загрузка) никогда не сообщается.

Регистр уставки `0x0100` принимает 0 (выкл.) или значение от 45 до 85 °C (`LINK_MIN_TARGET`–`LINK_MAX_TARGET`). Любое другое значение отклоняется исключением 0x03. Пока ошибка зафиксирована, любая запись в `0x0100` отклоняется исключением 0x02; ошибка проверяется первой.

#### Индикация LED

| Состояние | LED |
|-----------|-----|
| Ожидание связи (кадров ещё не было или удержание истекло) | медленный бегущий огонёк, шаг 1000 мс |
| Простой (уставка 0) | LED1 горит постоянно, короткая вспышка LED3 на каждый отправленный ответ |
| Нагрев | бегущий огонёк, шаг 500 мс |
| Удержание (связь молчит) | все три мигают синхронно, 4 Гц |
| Ошибка | обычные паттерны ошибок, см. «Как быть в случае ошибки». Ошибка `0x08` (потеря связи) возникает только в сборке pulse; если сохранена `0x08`, сборка UART быстро мигает LED1, как на шаге 1 калибровки |

#### Ошибки и удалённый сброс

| Код | Ошибка | Удалённый сброс |
|-----|--------|-----------------|
| `0x01` | Таймаут температуры | да |
| `0x02` | Нагреватель не отвечает | нет |
| `0x03` | Ручное отключение | да |
| `0x04` | Обрыв термистора воздуха | да |
| `0x05` | Обрыв термистора нагревателя | да |
| `0x06` | Перегрев нагревателя | нет |
| `0x07` | Перегрев воздуха | да |
| `0x08` | Потеря связи | да |
| `0xFF` | Неизвестная | нет |

Таблица задана как `FAULT_TABLE` в `config.h`. Ошибка остаётся зафиксированной, пока её не сбросят. Для удалённого сброса запишите код активной ошибки в holding-регистр `0x0101`. Запись проходит, только если выполнено всё:

- код совпадает с активной ошибкой, и для неё выше указано «да»;
- остались удалённые сбросы (3 за цикл питания; перезапуск питания их восстанавливает);
- показания были безопасными 5 с: оба термистора исправны, воздух минимум на 10 °C ниже `MAX_AIR_TEMP`, нагреватель минимум на 10 °C ниже `MAX_TEMP`.

При успехе плата стирает сохранённую ошибку, проверяет, что страница ошибки читается как стёртая, отвечает и перезапускается; после перезапуска уставка равна 0, а `last_clear_result` равен 1. Удержание MODE при включении по-прежнему сбрасывает ошибку локально.

Заметки для стороны Remote:

- Сбрасывайте одиночной записью регистра (функция 06). Запись FC 10, захватывающая `0x0101` и следующие регистры, может сбросить ошибку и перезапустить плату, даже если ответом пришло исключение.
- Многорегистровая запись, отклонённая на середине, сохраняет уже записанные регистры. После любого исключения перечитывайте состояние.
- На сброс отвечают только после стирания страницы ошибки. Если стирание не удалось, ответом будет исключение 0x04, плата не перезапускается и остаётся в ошибке, а попытка сброса израсходована. После успешного сброса `last_clear_result` после перезапуска равен 1.

#### Стендовый зонд

`tools/link_probe.py` требует Python с `pymodbus` 3.x и `pyserial` (`pip install "pymodbus>=3,<4" pyserial`):

```
python tools/link_probe.py COM5 read        # все регистры, расшифрованные
python tools/link_probe.py COM5 target 60   # уставка воздуха в °C (0 = выкл.)
python tools/link_probe.py COM5 clear 7     # сбросить активную ошибку с кодом 7
python tools/link_probe.py COM5 raw         # регистры без расшифровки и кадры на линии
```

Код возврата: 0 при успехе, 1 при таймауте или ответе с ошибкой, 2 при неверных аргументах.

### Сброс ошибки

Удерживайте кнопку MODE при старте до тех пор, пока светодиоды не поменяют индикацию. Ошибка будет стерта из flash и устройство продолжит обычную работу.

## Тонкая настройка

В случае когда есть подтверждение, что показания термистора отличаются от фактической температуры, можно воспользоваться функцией тонкой настройки, для этого необходимо измерить сопротивления соответствующих резисторов и записать их вместо дефолтных значений


```C++ title="Actual resistance of the pull-up resistors"
#define PULLUP_TH0 4700.0f
#define PULLUP_TH1 4700.0f
#define PULLUP_TH2 4700.0f
```
